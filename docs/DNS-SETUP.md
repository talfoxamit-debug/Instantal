# DNS Setup for Sending Domains

Exact records for every cold-email sending domain. Replace `getfoxstays.com`
with each domain you actually bought (the examples below use the plan's
suggested variants — **never** foxstays.com, seatophomes.com, or any revenue
domain).

Repeat this entire file once per sending domain.

---

## 1. SPF (TXT on the root)

| Host | Type | Value |
|---|---|---|
| `@` | TXT | `v=spf1 include:_spf.google.com ~all` |

One SPF record per domain, ever. If the registrar pre-created an SPF record,
edit it — do not add a second one (two SPF records = SPF fails entirely).

## 2. DKIM (TXT, generated by Google)

1. Google Admin console → Apps → Google Workspace → Gmail → **Authenticate email**.
2. Select the domain → **Generate new record** → key length **2048**.
3. Publish what Google gives you:

| Host | Type | Value |
|---|---|---|
| `google._domainkey` | TXT | `v=DKIM1; k=rsa; p=MIIBIjANBgkq...` (from Admin console) |

4. Back in the Admin console click **Start authentication**. Status must read
   "Authenticating email".

## 3. DMARC (TXT on `_dmarc`)

| Host | Type | Value |
|---|---|---|
| `_dmarc` | TXT | `v=DMARC1; p=quarantine; rua=mailto:dmarc@getfoxstays.com; aspf=s; adkim=s; pct=100` |

- `p=quarantine` from day 1 per the plan (Google's bulk-sender rules require
  at least `p=none`; quarantine is the stronger trust signal).
- Point `rua=` at a mailbox that exists — create a `dmarc@` alias/group on one
  of the inboxes so aggregate reports have somewhere to land.

## 4. Tracking subdomain (CNAME) — used from Phase 2

| Host | Type | Value |
|---|---|---|
| `t` | CNAME | `cname.vercel-dns.com` |

Then add `t.getfoxstays.com` as a domain on the Vercel project so
`/api/track/*` and `/api/unsubscribe/*` resolve on it. Open/click tracking
stays OFF by default (plan §5.5) — the unsubscribe endpoint is the reason
this subdomain exists.

## 5. Root redirect (trust signal)

Redirect the sending domain's root to the venture's real site:

- `getfoxstays.com` → `https://foxstays.com` (301)
- `tryseatop.com` → `https://seatophomes.com` (301)

Use the registrar's forwarding, or a tiny Vercel project with a redirect —
either is fine. A sending domain that resolves to nothing looks disposable.

## 6. Google Postmaster Tools

1. https://postmaster.google.com → Add domain → each sending domain.
2. Publish the verification TXT record it gives you.
3. This is the real reputation scoreboard — check domain reputation and spam
   rate weekly (spam rate must stay under 0.3%, ideally under 0.1%).

---

## Verification commands

Run after records propagate (up to an hour, usually minutes):

```bash
dig +short TXT getfoxstays.com            # expect the v=spf1 record
dig +short TXT google._domainkey.getfoxstays.com   # expect v=DKIM1...
dig +short TXT _dmarc.getfoxstays.com     # expect v=DMARC1...
dig +short CNAME t.getfoxstays.com        # expect cname.vercel-dns.com
curl -sI https://getfoxstays.com | head -3 # expect 301 to the real site
```

Or one-stop web checks: https://mxtoolbox.com/SuperTool.aspx (SPF/DKIM/DMARC
lookups) and Google Admin Toolbox `checkmx`.

## Send-window rule

The **domain aging clock** starts when DNS goes live — no real sends before
day 10-14, regardless of how finished the code is. See
`docs/PHASE-0-CHECKLIST.md`.
